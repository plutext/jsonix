# TypeScript contract test

The runtime's data representation is a contract with the declaration files that
`jsonix-schema-compiler -generateTypeScript` emits (see `docs/change-requests/jsonix-CR-001-typescript-consumers.md`).
This directory holds the compiler's output for the purchase order schema and three checks over it:

| Check | Command | What it proves |
|-------|---------|----------------|
| `usage.ts` | `npm run typecheck` | Generated element types flow through `types/main.d.ts` without casts; the `@ts-expect-error` lines prove the types bite. |
| `typescript.js` | `npm test` (part of the nodeunit suite) | Unmarshalling `po.xml` with `PurchaseOrder.std.js` produces exactly the shape `PurchaseOrder.d.ts` declares. |
| `esm-smoke.mjs` | `npm run test:esm` | `import { Jsonix } from '@mitre/jsonix'` and `import { PO } from './PurchaseOrder.mjs'` work together in Node ESM. |

## Generated files

`PurchaseOrder.d.ts`, `PurchaseOrder.std.d.ts`, `PurchaseOrder.std.js`, `PurchaseOrder.mjs` and
`PurchaseOrder.d.mts` were generated by jsonix-schema-compiler at commit `09dee1d`
(2.3.10-SNAPSHOT, CR-005) from `purchaseorder.xsd` and `bindings.xjb` in this directory:

```
java -jar jsonix-schema-compiler-full-<version>.jar -generateTypeScript -d . purchaseorder.xsd -b bindings.xjb
```

Regenerate them (from this directory, JDK 11+) when the compiler's output format changes
deliberately; its output is deterministic, so the diff shows only the intended change. Do not edit
them by hand. `bindings.xjb` uses the Jakarta binding namespace, which the current compiler
requires.
