# Change requests

Numbered proposals for changes to this fork of the Jsonix runtime (`plutext/jsonix`, published as
`@docx4j/jsonix`; continues MITRE's `@mitre/jsonix`, itself forked from `highsource/jsonix`). They are prefixed `jsonix-` to keep them distinct
from the change requests of the sibling `jsonix-schema-compiler` repository, which this runtime's
proposals frequently depend on.

| CR | Title | Depends on | Status |
|----|-------|------------|--------|
| [jsonix-CR-001](jsonix-CR-001-typescript-consumers.md) | Support TypeScript consumers of compiler-generated declarations and ES-module mappings | compiler CR-005 | Implemented 2026-09-06 (3.1.0) |
| [jsonix-CR-002](jsonix-CR-002-parent-pointers-and-deep-copy.md) | Parent pointers (`PARENT`) and `Jsonix.Util.deepCopy` for unmarshalled objects, mirroring docx4j's `-Xparent-pointer` / `-Xdocx4j-copy` | jsonix-CR-001; companion compiler CR-006 | Implemented 2026-09-07 (3.2.0) |
| [jsonix-CR-003](jsonix-CR-003-namespace-declarations-and-dom-typings.md) | Namespace declarations where first used, `declareNamespaces` and per-marshal `namespacePrefixes` options (retires the facade's stripping pass), `xml` never redeclared, `Jsonix.DOM` in the typings | jsonix-CR-001; requested by objects CR-001 | Part 1 (typings: `Jsonix.DOM`, `Context.namespacePrefixes`) implemented 2026-09-15 as 3.2.1; part 2 (namespace declarations) deferred to 3.3.0 |
| [jsonix-CR-004](jsonix-CR-004-xml-1-0-line-ending-normalisation.md) | Parse XML 1.0 documents with XML 1.0 line-ending normalisation: raw U+0085 and U+2028 survive unmarshal in Node (xmldom applies the 1.1 rule by default) | none; requested by core-ts CR-001 §9 | Implemented 2026-09-24 (3.3.0) |
| [jsonix-CR-005](jsonix-CR-005-bundled-runtime-loses-xmldom.md) | A bundled runtime loses `@xmldom/xmldom`: the UMD footer injects it through `amdefine`, which no bundler can satisfy, so the factory is called with no dependencies and Node bundles reach for `XMLHttpRequest` | none; requested by objects CR-005 §6.2 | Implemented 2026-09-24 (3.3.0), as reviewed in section 7 |
| [jsonix-CR-006](jsonix-CR-006-report-what-is-dropped-and-record-what-is-written.md) | Report what unmarshalling drops (an unexpected element or attribute, located through the DOM node the input stands on) and record what marshalling writes (every element against the value it came from, wildcard DOM content included): four optional context callbacks, and a located error for a value of the wrong type | none; requested by core-ts CR-002 §27 and core-ts CR-006 | Implemented 2026-09-27 (3.4.0), three amendments in section 9 |
| [jsonix-CR-007](jsonix-CR-007-on-off-booleans.md) | `on` and `off` read as booleans (ECMA-376 Transitional's `ST_OnOff`, which Word reads and pandoc writes), printed `true`/`false` as before: a toggle attribute holding either threw, and a valid document would not open | none; requested by core-ts for the editor | Implemented 2026-10-16 (3.4.1) |
| [jsonix-CR-008](jsonix-CR-008-unmarshal-on-element.md) | An unmarshal-side `onElement(element, value)`: once per element read as a typed object, with the source element itself, children before their parent; the counterpart of CR-006's marshal-side callback, which objects CR-011 needs to record the prefixes an `mc:Choice`'s `Requires` names | none; requested by objects-ts for its CR-011 | Implemented 2026-10-20 (3.5.0) |
| [jsonix-CR-009](jsonix-CR-009-schema-defaults-on-read.md) | Schema defaults on read: `AttributePropertyInfo` keeps the mapping's `defaultValue`, and `Context.getDefaultValue(typeName, propertyName)` / `valueOrDefault(object, propertyName)` return it for an absent attribute, as a JAXB getter does; unmarshal and marshal unchanged, so absent stays absent; element defaults out | none in the runtime; WordprocessingML adoption waits on docx4j #697 and CR-059; requested by Jason via objects-ts | Implemented 2026-10-24 (3.6.0) |
| [jsonix-CR-010](jsonix-CR-010-invalid-attribute-values-to-the-caller.md) | An attribute value its type refuses (`w:b w:val="FALSE"`, `w:u w:val="Single"`) goes to a per-call `onInvalidValue(text, propertyInfo, classInfo, node, error)` instead of failing the whole part, with `onUnprintableValue` on the marshal side for a kept string; the runtime stays schema-neutral, and Word's readings and their scope (`classInfo.module.name`) belong to the facade | none; requested by core-ts for its CR-015 | Implemented 2026-10-24 (3.7.0) |
| [jsonix-CR-011](jsonix-CR-011-marshal-side-adapters.md) | Marshal-side adapters, the runtime's counterpart of JAXB's `XmlAdapter`: per-call `onAttributeValue(value, text, owner, propertyInfo, classInfo)` rewrites (string), omits (`null`) or keeps (`undefined`) an attribute that prints, and `omitElement(value, name, typeInfo, propertyInfo, classInfo)` leaves an element out; marshal-only, the tree unchanged, nothing changes unset | none; requested by objects-ts for its CR-013 phase C | Proposed 2026-10-24 |
